# Shiori 存档系统详细说明

## 概述

Shiori 引擎提供了一套完整的存档与导航系统，包含五个核心模块。这些模块采用模块化设计，既可独立运行，又能通过统一的数据源实现状态同步，为开发者提供了灵活的游戏进度管理方案。

---

## 1. 进度管理（saves.html）

### 功能定位
最原始的存档管理系统，提供基础的API接口支持，是整个存档体系的数据基石。

### 技术实现细节
- **数据存储**：通过 `localStorage.gameProgress` 存储游戏进度数据
- **场景追踪**：使用 `sceneMarkers` 数组记录玩家已访问的所有场景节点
- **展示方式**：简单的列表式展示，无复杂的UI交互和视觉效果
- **数据结构**：
  ```javascript
  {
    sceneMarkers: ["scene1", "scene2", "scene3"],  // 已访问场景列表
    currentScene: "scene5",                         // 当前所在场景
    currentLine: 42,                                // 当前剧情行号
    timestamp: 1716000000000                        // 最后更新时间戳
  }
  ```

### 当前状态
仅实现基础的数据罗列功能，缺少直观的可视化展示和交互操作。主要作为底层数据接口存在。

### 适用场景与局限性
**优势：**
- 轻量级实现，性能开销极小
- 作为其他高级功能的底层数据源
- 为成就系统、统计面板提供原始数据支持
- 开发者调试时快速查看游戏进度状态

**局限：**
- 无法直接进行存档/读档操作
- 缺乏用户友好的界面交互
- 不支持多存档位管理
- 无视觉反馈和状态提示

### 与其他系统的关系
- 为 `archive.html` 提供实时进度数据
- 为 `flowchart.html` 提供场景解锁判断依据
- 是 `story.html` 潜在的数据扩展基础

## 2. 小故事鉴赏（story.html）

### 功能定位
独立的小故事/番外篇鉴赏模块，用于展示与主线剧情解耦的额外内容。

### 技术实现细节
- **内容管理**：完全硬编码实现，未接入游戏进度API
- **展示机制**：静态内容展示，不支持动态解锁机制
- **架构设计**：独立的HTML结构，与主线剧情完全解耦
- **数据隔离**：不读取也不写入 `localStorage.gameProgress`

### 当前状态
基础框架已完成，待填充具体内容。目前处于预留接口状态。

### 适用场景
- **角色番外故事**：展示角色的背景故事、个人线剧情
- **背景设定集**：世界观介绍、角色档案、术语解释
- **DLC内容入口**：付费或免费追加内容的独立展示平台
- **隐藏剧情查阅**：达成特定条件后解锁的特殊剧情回顾
- **二创作品收录**：官方认可的玩家创作内容展示区

### 未来扩展方向
**可实现的增强功能：**
1. **动态解锁机制**：根据 `saves.html` 中的进度数据解锁对应小故事
2. **收藏系统**：允许玩家标记喜爱的小故事
3. **阅读统计**：记录每个小故事的阅读次数和时长
4. **分类筛选**：按角色、类型、时间等维度进行分类展示
5. **搜索功能**：支持关键词检索小故事内容

### 与主线系统的差异
| 特性 | story.html | 主线系统 |
|------|-----------|---------|
| 数据依赖 | 无 | 依赖 localStorage |
| 解锁机制 | 静态/硬编码 | 动态进度追踪 |
| 更新频率 | 低频（版本更新） | 高频（实时同步） |
| 交互复杂度 | 低 | 高 |

## 3. 行级存档恢复（archive.html）

### 功能定位
精细化的存档管理系统，支持精确到剧情行的保存与恢复，是玩家最常用的核心存档功能。

### 技术实现细节

#### 数据存储结构
```javascript
{
  archives: [
    {
      id: 1,                                    // 存档序号
      name: "最终决战前",                        // 自定义名称
      sceneFile: "scene_final.html",            // 场景文件名
      lineIndex: 156,                           // 剧情行索引
      timestamp: 1716000000000,                 // 保存时间戳
      textPreview: "你准备好了吗？...",          // 文本预览（前50字符）
      gameState: {                              // 完整游戏状态快照
        affinity: { "yn": 85 },                 // 好感度数据
        flags: { "met_boss": true },            // 剧情标志位
        inventory: ["key_item"]                 // 物品栏状态
      }
    }
  ]
}
```

#### 核心功能
1. **完整上下文保存**：
   - 当前场景文件名
   - 精确的剧情行号
   - 所有游戏变量状态（好感度、标志位、物品等）
   - 保存时间和自定义名称

2. **多存档位管理**：
   - 支持无限数量的存档（受限于浏览器存储容量）
   - 每个存档位独立存储，互不干扰
   - 支持双击编辑存档名称

3. **智能返回机制**：
   - 从存档页返回时自动定位到原剧情位置
   - 显示"返回当前页面"按钮并高亮当前节点
   - 保持流畅的游戏体验，避免迷失方向

4. **数据导入导出**：
   - 支持将所有存档导出为 JSON 文件
   - 可从 JSON 文件导入存档数据
   - 便于备份、分享和跨设备迁移

### 当前状态
功能完善，支持行级精度的存档/读档操作，用户体验流畅。

### 适用场景
- **关键选择前存档**：在重要分支点前手动创建存档点
- **分支路线测试**：快速切换不同选择路线进行对比
- **困难章节挑战**：在高难度段落反复尝试直至通关
- **多结局收集**：回溯到关键点探索不同结局
- **进度备份**：定期导出存档防止数据丢失

### 性能优化策略
1. **防抖机制**：F5 快速存档带有 1 秒冷却时间，防止长按重复触发
2. **懒加载**：存档列表仅在打开页面时加载，不影响主游戏性能
3. **增量更新**：仅保存变化的数据字段，减少存储开销
4. **压缩存储**：对大型状态数据进行序列化压缩

### 与其他系统的协同
- 读取 `saves.html` 的实时进度作为默认存档参考
- 为 `flowchart.html` 提供当前节点的精确位置信息
- 导出的 JSON 可作为 `story.html` 的内容来源之一

## 4. 剧本流程图（flowchart.html）- 正式版

### 功能定位
可视化的剧本导航系统，根据玩家实际游戏进度动态解锁节点，提供沉浸式的剧情回顾体验。

### 技术实现细节

#### 解锁判断逻辑
```javascript
// 从 saves.html 读取已访问场景
const visitedScenes = localStorage.gameProgress.sceneMarkers || [];

// 判断节点是否解锁
function isNodeUnlocked(sceneId) {
  return visitedScenes.includes(sceneId);
}

// 渲染节点状态
if (isNodeUnlocked(node.id)) {
  renderNormalNode(node);      // 正常显示，可点击
} else {
  renderLockedNode(node);      // 显示"？？？"，不可点击
}
```

#### 自动布局引擎
1. **垂直位置计算**：
   - 根据节点 ID 的层级深度确定 Y 轴位置
   - 示例：`scene1` → level 1, `scene1_2` → level 2
   - 每层固定间距（如 120px）

2. **水平分布调整**：
   - 使用 x/y 百分比偏移微调节点位置
   - 避免节点重叠和连线交叉
   - 支持手动配置特殊节点的偏移量

3. **SVG 正交连线**：
   - 智能绘制节点间的关系路径
   - 采用直角折线而非斜线，提升可读性
   - 自动避让其他节点和连线

#### 智能导航功能
- **当前位置高亮**：从剧情页进入时，高亮显示当前所在节点
- **一键返回**：提供"返回当前页面"按钮，点击后恢复到原剧情行
- **路径追溯**：可通过点击已解锁节点快速跳转到任意历史场景

### 当前状态
核心功能完成，支持动态解锁和智能导航，视觉效果清晰美观。

### 适用场景
- **剧情回顾**：玩家重温已体验的剧情路线
- **路线规划**：在多结局游戏中辅助规划探索路径
- **遗漏补全**：发现未访问的场景节点，引导玩家补全
- **结构理解**：可视化展示复杂分支结构，降低理解门槛
- **成就追踪**：配合成就系统显示"全场景探索"进度

### 布局算法示例
```javascript
// 简化的布局计算逻辑
function calculateNodePosition(nodeId, depth, xOffset) {
  const baseY = depth * 120;  // 每层120px
  const baseX = 50 + xOffset; // 基准居中，加偏移量
  
  return {
    x: `${baseX}%`,
    y: `${baseY}px`
  };
}

// 节点配置示例
const nodes = [
  { id: "scene1", depth: 1, xOffset: 0 },
  { id: "scene2", depth: 2, xOffset: -20 },  // 向左偏移
  { id: "scene3", depth: 2, xOffset: 20 },   // 向右偏移
  { id: "scene4", depth: 3, xOffset: 0 }     // 合并节点
];
```

## 5. 剧本流程图（flowchart_debug.html）- 调试版

### 功能定位
开发调试专用的完整流程图查看器，无视游戏进度限制，始终显示所有节点和连线。

### 技术实现细节

#### 硬编码场景数据
```javascript
// 调试版直接使用完整的场景定义
const allScenes = [
  { id: "scene1", label: "初次相遇", connections: ["scene2", "scene3"] },
  { id: "scene2", label: "图书馆约会", connections: ["scene4"] },
  { id: "scene3", label: "咖啡厅闲聊", connections: ["scene4"] },
  { id: "scene4", label: "告白场景", connections: ["ending_good", "ending_bad"] },
  // ... 所有场景，包括测试分支和调试标记点
];

// 移除解锁判断，所有节点始终可见
function renderNode(node) {
  renderNormalNode(node);  // 永远以正常状态渲染

```

#### 简化逻辑
- **无解锁判断**：跳过 `sceneMarkers` 读取和比对逻辑
- **无状态同步**：不监听 `localStorage` 变化
- **相同布局引擎**：复用正式版的布局和连线算法，保证视觉效果一致
- **额外调试信息**：可显示节点 ID、连接线数量等元数据

### 当前状态
功能完整，专为开发者设计，加载速度快，无运行时开销。

### 适用场景
- **剧本结构设计**：在编写阶段快速预览整体结构
- **分支路线调试**：验证各分支的逻辑正确性和连通性
- **布局优化**：调整节点位置和连线走向，避免视觉混乱
- **新增节点测试**：确认新场景在流程图中的位置和连接关系
- **合并节点验证**：检查多条分支是否正确汇聚到同一节点
- **教学演示**：向团队成员展示完整的故事脉络
- **QA 测试**：确保所有路线都可到达，无死胡同

### 与正式版的详细对比

## 系统架构总览

### 模块化设计原则

#### 1. 独立运行
每个系统均可单独使用，无需依赖其他模块：
- 可仅使用 `archive.html` 而不启用 `flowchart.html`
- 可在项目中删除 `story.html` 而不影响其他功能
- 各模块间无硬性耦合，便于按需裁剪

#### 2. 数据互通
共享 `localStorage.gameProgress` 作为统一数据源：
```javascript
// 统一的数据结构
localStorage.gameProgress = {
  sceneMarkers: ["scene1", "scene2"],  // saves.html 写入，flowchart.html 读取
  currentScene: "scene5",               // archive.html 更新，flowchart.html 高亮
  currentLine: 42,                      // archive.html 保存，用于智能返回
  archives: [...],                      // archive.html 独占管理
  lastUpdate: 1716000000000             // 所有模块共同维护
};
```

#### 3. 按需配置
可根据项目需求灵活增减功能模块：
- **小型项目**：仅保留 `archive.html` 即可满足基本需求
- **中型项目**：增加 `flowchart.html` 提升导航体验
- **大型项目**：启用全部模块，构建完整的进度管理体系
- **调试阶段**：使用 `flowchart_debug.html` 加速开发迭代

#### 4. 首次编译友好
所有新增功能均为纯前端实现：
- 不引入额外依赖库（无 npm install）
- 不修改核心引擎代码（engine.js 保持不变）
- 不影响首次编译所需的文件结构
- 编译流程与原有项目完全兼容

### 存档隔离机制

#### 调试版与正式版的数据隔离

**隔离原理：**
- **正式版（Shiori.exe）**：使用标准 WebView2 用户数据目录
- **调试版（Shiori_debug.exe）**：使用独立的调试版用户数据目录
- 两者的 `localStorage` 完全隔离，互不干扰

**目录结构示例：**
```
Shiori.exe.WebView2/EBWebView/Default/Local Storage/
  └── leveldb/  ← 正式版存档数据

Shiori_debug.exe.WebView2/EBWebView/Default/Local Storage/
  └── leveldb/  ← 调试版存档数据
```

**实际应用价值：**
1. **开发阶段**：
   - 可在调试版中自由测试新功能
   - 不会影响正式版中玩家的真实存档
   - 可随时重置调试版数据而不担心误删玩家进度

2. **发布前检查**：
   - 在打包分发正式版前，清除调试过程中产生的测试存档
   - 通过窗口菜单的 `调试` → `清除所有存档` 一键清理
   - 确保正式发布版本的存档数据干净整洁

3. **数据安全**：
   - 开发者测试环境与玩家生产环境完全独立
   - 避免测试数据污染正式发布版本
   - 降低因调试操作导致玩家数据丢失的风险

#### 清除存档功能
调试版提供一键清除所有存档的功能：
- **位置**：窗口菜单 → `调试` → `清除所有存档`
- **确认机制**：执行前弹出二次确认对话框，防止误操作
- **清除范围**：
  - 所有剧本的进度存档（sceneMarkers）
  - 所有手动创建的存档位（archives）
  - 选择记录和剧情标志位（flags）
  - 好感度数据（affinity）
- **保留内容**：
  - 游戏设置（音量、显示模式等）
  - 配置文件（bg_config.js 等）
  - 资源文件（图片、音频、视频）

## 常见问题解答

### Q1: 为什么需要这么多存档系统？
**A:** 每个系统针对不同场景优化：
- `saves.html`：底层数据接口，供其他系统调用
- `story.html`：独立内容展示，与主线解耦
- `archive.html`：玩家日常使用的核心存档功能
- `flowchart.html`：可视化导航，提升沉浸感
- `flowchart_debug.html`：开发工具，加速迭代

### Q2: 存档数据会丢失吗？
**A:** 存档存储在浏览器的 `localStorage` 中：
- **正常情况下**：数据持久保存，关闭程序后仍存在
- **可能丢失的情况**：
  - 用户手动清除浏览器数据
  - 卸载并重新安装游戏（未备份存档）
  - 浏览器存储空间不足被自动清理
- **建议**：定期使用 `archive.html` 的导出功能备份存档

### Q3: 如何在不同设备间转移存档？
**A:** 使用 `archive.html` 的导入导出功能：
1. 在旧设备上点击"导出所有存档"，保存 JSON 文件
2. 将 JSON 文件复制到新设备
3. 在新设备上点击"导入存档"，选择 JSON 文件
4. 存档立即生效，可继续游戏

### Q4: 调试版和正式版可以共存吗？
**A:** 可以，且推荐共存：
- 两者使用不同的可执行文件名（Shiori.exe vs Shiori_debug.exe）
- 存档数据完全隔离，互不影响
- 可同时安装在同一目录下
- 开发者日常使用调试版，玩家使用正式版

### Q5: 流程图节点太多导致混乱怎么办？
**A:** 优化建议：
1. **合理分组**：将相关场景放在同一区域
2. **使用偏移量**：通过 x/y 百分比微调节点位置
3. **分层展示**：考虑实现折叠/展开功能（未来扩展）
4. **颜色区分**：用不同颜色标识不同类型的节点（未来扩展）
5. **参考调试版**：在 flowchart_debug.html 中预览完整布局后再调整

### Q6: 如何自定义存档系统的样式？
**A:** 修改对应的 CSS 文件：
- `saves.html` → 编辑 `<style>` 标签内的样式
- `archive.html` → 修改存档卡片的 `.archive-card` 类
- `flowchart.html` → 调整节点的 `.node` 类和连线的 `.connection` 类
- 所有样式均使用标准 CSS，支持响应式设计

### Q7: 存档系统支持云同步吗？
**A:** 当前版本不支持原生云同步，但可通过以下方式实现：

2. **第三方工具**：配合网盘软件（如 OneDrive、Dropbox）同步存档文件夹
3. **未来扩展**：可集成 Web API 实现自动云同步（需后端支持）

### Q8: 如何为故事添加解锁条件？
**A:** 扩展 `story.html` 的实现：
```javascript
// 在 story.html 中添加解锁判断
const storyRequirements = {
  "extra_story_1": {
    requiredScenes: ["scene10", "scene15"],  // 需访问这些场景
    minAffinity: { "yn": 80 }              // 好感度要求
  }
};

function isStoryUnlocked(storyId) {
  const req = storyRequirements[storyId];
  const progress = localStorage.gameProgress;
  
  // 检查场景访问情况
  const scenesVisited = req.requiredScenes.every(scene => 
    progress.sceneMarkers.includes(scene)
  );
  
  // 检查好感度
  const affinityMet = Object.entries(req.minAffinity).every(([char, value]) => 
    (progress.affinity?.[char] || 0) >= value
  );
  
  return scenesVisited && affinityMet;
}
```
