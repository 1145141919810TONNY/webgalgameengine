# Shiori Engine Launcher - 编译与部署指南

> **重要提示：**
> - 由于生成的 exe 文件较大（约 200MB+），无法上传至 GitHub
> - **您需要自行编译项目**才能获得可执行文件
> - 默认采用单文件打包模式，也可根据需要修改为多文件模式（见下方说明）

## 快速开始

### 1. 编译程序

双击运行 `build_fix.bat` 即可开始编译。

```bash
cd Shiori
.\build_fix.bat
```

**首次编译说明：**
- 首次编译需要下载安装依赖（PyQt6、PyQt6-WebEngine、PyInstaller 等），耗时约 5-10 分钟
- 后续编译只需 1-2 分钟
- 编译过程中会自动检测并安装缺失的依赖

**编译输出：**
编译完成后，会在 `Shiori/dist/` 目录生成两个文件：
- `Shiori.exe` - 标准版（无控制台窗口）
- `Shiori_debug.exe` - 调试版（带控制台窗口，可查看日志）

## 单文件 vs 多文件打包

### 默认配置：单文件打包

当前项目默认使用**单文件打包模式**（`--onefile`），所有依赖都打包进单个 exe 文件中。

**优点：**
- 部署简单：只需复制 exe 文件
- 无需额外文件夹：没有 `_internal` 或 `dependency` 目录
- 便携性强：exe 可独立运行

**缺点：**
- 体积较大（约 200MB+）
- 首次启动需要解压到临时目录（10-30 秒）
- 占用临时空间

### 可选配置：多文件打包

如果您希望减小体积或加快启动速度，可以修改为多文件模式。

**提示：**
- 可以通过修改 `shiori.spec` 和 `shiori_debug.spec` 文件来实现多文件打包
- 需要将 `EXE` 中的 `a.binaries` 和 `a.datas` 移除，并添加 `COLLECT` 步骤
- 修改后重新编译即可生成多文件版本

**注意：**
- 修改打包模式需要熟悉 PyInstaller 配置
- 多文件模式部署时需要保持文件夹结构完整（包含 `_internal` 目录）
- 如果不确定，建议使用默认的单文件模式

## 依赖说明

### 核心依赖

| 依赖项 | 最低版本 | 说明 |
|--------|---------|------|
| Python | 3.10.0+ | 必须安装 Python 运行时 |
| PyQt6 | 6.5.0+ | GUI 框架 |
| PyQt6-WebEngine | 最新 | 内置 Chromium 浏览器引擎 |
| PyInstaller | 6.0.0+ | Python 打包工具 |

### 自动检测与安装

`build_fix.bat` 脚本会自动执行以下操作：
1. 检测 Python 是否安装
2. 检查 PyQt6 和 PyQt6-WebEngine 是否已安装
3. 如果缺少依赖，自动使用 pip 安装
4. 验证安装是否成功

**无需手动安装依赖！** 只需确保已安装 Python 3.10+ 即可。

## 部署步骤

### 方法一：使用部署脚本（推荐）

编译完成后，运行部署脚本自动将文件复制到项目根目录：

```bash
cd Shiori
.\deploy_to_root.bat
```

脚本会自动执行以下操作：
1. 检查编译输出是否完整
2. 复制 `Shiori.exe` 和 `Shiori_debug.exe` 到根目录
3. 验证 `shiori engine` 文件夹是否存在
4. 清理根目录中的旧文件（build、dist、__pycache__ 等）

### 方法二：手动部署

如果不想使用脚本，可以手动操作：

1. 将 `Shiori/dist/Shiori.exe` 复制到项目根目录
2. 将 `Shiori/dist/Shiori_debug.exe` 复制到项目根目录
3. 确保根目录存在 `shiori engine` 文件夹
4. 双击 `Shiori.exe` 运行

### 最终目录结构

```
shiori/                          # 项目根目录
── Shiori.exe                   # 标准版启动器（约 200MB）
├── Shiori_debug.exe             # 调试版启动器
└── shiori engine/               # 引擎文件夹（不被打包，以前所有的文件都放在这个文件夹中）
    ├── index.html               # 入口文件
    ├── api/                     # API 接口
    ├── assets/                  # 资源文件（图片、音频等）
    ├── scenes/                  # 游戏场景
    └── ...
```

**重要提示：**
- `Shiori.exe` 是单文件打包，包含所有 Python/Qt 依赖
- `shiori engine` 文件夹必须与 exe 同级，且**不能**被打包进 exe
- 用户可以随时修改 `shiori engine` 中的内容，无需重新编译

## 常见问题

### Q: 编译后 exe 只有 200MB，正常吗？

**A:** 正常！这是 UPX 压缩的结果。标准版启用了 UPX 压缩，可以将文件大小压缩 30-50%。

### Q: 首次启动为什么很慢？

**A:** 单文件模式下，PyInstaller 需要将依赖解压到临时目录（`%TEMP%\_MEIxxxxx`）。首次启动需要 10-30 秒，后续启动会快一些。

### Q: 如何修改游戏内容？

**A:** 直接修改 `shiori engine` 文件夹中的文件即可（完全和以前的开发方式一致！）：
- 修改 HTML 场景：编辑 `scenes/*.html`
- 替换图片：覆盖 `assets/bg/`、`assets/cg/` 等
- 添加音频：放入 `assets/bgm/`、`assets/audio/`

**无需重新编译 exe！**

### Q: 版权信息在哪里查看？

**A:** 
1. 右键 `Shiori.exe` → 属性 → 详细信息
2. 或在程序中点击"帮助" → "关于"

提示：你可以根据需要修改你想要的内容，当然如果能保留原本的版权信息就更好了！

### Q: 调试版和标准版有什么区别？

| 特性 | 标准版 | 调试版 |
|------|--------|--------|
| 控制台窗口 | 无 | 有 |
| 调试日志 | 不输出 | 输出到控制台 |
| 开发者工具 | F12 可用 | F12 可用 |
| 文件大小 | 较小 | 较大 |

**建议使用：**
- 发布给用户：标准版（`Shiori.exe`）
- 开发调试：调试版（`Shiori_debug.exe`）
